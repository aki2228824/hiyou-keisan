# 療養介護サービス提供実績記録票

入院患者が1か月に利用した日用品・食事などの費用を自動集計し、請求書（PDF）を出力する社内向けWebアプリケーションです。

---

## 主な機能

| 機能 | 内容 |
|------|------|
| **日次入力** | 患者ごとに日用品の使用数・食事回数・サービス提供状況を1か月分まとめて入力 |
| **月次集計** | 病棟・月を指定して全患者の費用を一覧表示 |
| **PDF出力** | 患者ごとの請求書をPDFで出力 |
| **マスタ管理** | 患者・物品・日用品単価・ユーザーの登録・編集・削除 |
| **ロール制御** | 管理者／一般スタッフ／閲覧のみ の3段階アクセス制御 |
| **週次使用量レポート** | 毎週月曜6:00に前週の日用品使用量を品目別に集計し、Difyワークフローへ送信（Dify側でメール配信） |

---

## 画面構成

```
├── 日次入力
│   ├── 病棟選択（2階 / 3階 / 4階）
│   ├── 患者選択
│   └── 1か月分の日次入力テーブル
│       ├── サービス提供の状況・入院外泊時加算・入院時支援特別加算
│       ├── 朝食・昼食・夕食（回数）
│       └── 日用品項目（入浴〜洗濯 など）
│
├── 月次集計
│   ├── 病棟選択
│   └── 患者別 食事費・日用品費・合計金額一覧
│
└── マスタ管理
    ├── 患者管理
    ├── 物品管理
    ├── 日用品単価（月ごと設定・翌月以降引き継ぎ）
    └── ユーザー管理
```

## セットアップ

### 必要環境

- Node.js 20 以上（推奨は現行の LTS。2026年11月時点では 26 系）

### インストールと起動

```bash
git clone https://github.com/aki2228824/hiyou-keisan.git
cd hiyou-keisan
npm install
node server/index.js
```

ブラウザで `http://localhost:3000` にアクセスしてください。

### 初期ログイン情報

| ユーザーID | パスワード | ロール |
|-----------|-----------|--------|
| admin | admin123 | 管理者 |

> 初期管理者は、ユーザーが1人も登録されていない初回起動時にだけ自動作成されます（そのとき起動ログにも表示されます）。
> ログイン後、マスタ管理 → ユーザー管理からパスワードを変更してください。

## 週次使用量レポート（Dify連携）

毎週月曜 6:00（JST）に前週（月〜日）の日用品使用量を品目別・病棟別に集計し、Dify のワークフローAPIへ送信します。メール本文の生成と配信は Dify 側で行います。

**送信するデータには個人情報を含めません。** 患者名・patient_id・受給者証番号・部屋番号は一切送らず、品目別／病棟別の集計値と在院患者数のみを送信します。

### 集計仕様

- 対象期間：前週の月曜〜日曜（比較対象は前々週の月曜〜日曜）
- 対象品目：`items.active=1` の全品目。ただし除外品目（**入浴・バスタオル・小タオル**）と、先週・前々週とも0の品目は除外
  - 入浴＝サービス、タオル類＝リネン業者のレンタル品のため補充目安の対象外
  - 除外リストは [server/services/weeklyUsage.js](server/services/weeklyUsage.js) の `EXCLUDED_ITEM_NAMES` 定数（items.name と完全一致で判定）
  - 除外が効くのは週次レポートの集計のみ。月次集計・請求書PDFなど請求側の処理には影響しません
- 並び順：先週使用量の多い順
- フラグ（判定はすべてサーバー側で行い、LLMには計算させません）
  - `急増`：増減率 +30% 以上 かつ 先週合計 10 以上
  - `使用停止`：前々週に使用があり、先週が0
  - 前々週が0の品目（新規使用）は増減率を計算できないため `pct: null`・フラグなし
  - しきい値は [server/services/weeklyUsage.js](server/services/weeklyUsage.js) 冒頭の定数（`SPIKE_PCT` / `SPIKE_MIN`）で変更できます
- 退院済み患者（`patients.active=0`）の期間中の実績も含みます
- 本機能はDBの**読み取りのみ**で、書き込み・保存は行いません

### 環境変数（.env）

`.env.example` をコピーして `.env` を作成してください（`.env` はGit管理外です。APIキーをコミットしないこと）。

| 変数 | 内容 |
|------|------|
| `DIFY_API_URL` | DifyワークフローのAPI URL（例：`https://api.dify.ai/v1/workflows/run`） |
| `DIFY_API_KEY` | Difyで発行したAPIキー（`app-` で始まる文字列） |
| `EXPORT_ENABLED` | `true` のときだけ週次ジョブを登録する |
| `EXPORT_CRON` | cron書式（既定 `0 6 * * 1` ＝ 毎週月曜6:00） |
| `EXPORT_DRY_RUN` | `true` にすると自動実行時もDifyへ送信せずログのみ記録 |
| `TZ` | `Asia/Tokyo` |
| `SESSION_SECRET` | ログイン状態（セッション）の署名に使う秘密の文字列。本番運用では長いランダム文字列を設定する（未設定時は既定値。変更すると全員が再ログインになる） |
| `PORT` | 待ち受けポート番号（未設定時は `3000`） |
| `DB_PATH` | データベースファイルの保存先（未設定時は `data/hiyou.db`。親フォルダが無ければ自動作成） |
| `PDF_CONCURRENCY` | 請求書PDFを同時に生成する数の上限（未設定時は `2`。超えた分は順番待ち） |

`.env` は起動時の作業フォルダに関係なく、プロジェクト直下のものが読み込まれます。

### 手動実行API（管理者のみ）

```
POST /api/export/weekly-usage/run
  ?dry=1             Difyへ送らず集計JSONをそのまま返す（同期・テスト用）
  ?date=YYYY-MM-DD   基準日を指定して過去週を集計する（テスト用）
```

`dry` なしの実行は、集計後すぐに `202 Accepted`（対象期間・品目数）を返し、Dify への送信とリトライはバックグラウンドで行います（リトライで最大21分かかるため）。結果は `data/export.log` を確認してください。

```bash
# 管理者でログインしてドライラン
curl -c cookie.txt -H "Content-Type: application/json"   -d '{"username":"admin","password":"admin123"}' http://localhost:3000/api/auth/login
curl -b cookie.txt -X POST "http://localhost:3000/api/export/weekly-usage/run?dry=1"
```

### 送信の失敗時

Dify へ送れなかった場合は 1分 → 5分 → 15分 の間隔で最大3回リトライします。最終的に失敗してもサーバー本体は停止せず、`data/export.log` にエラーを記録します。

### 運用上の注意

- PM2 等で複数プロセスを起動すると cron が重複実行されます。**単一インスタンス運用が前提**です
- ログ `data/export.log` は追記のみです。肥大化する場合は定期的に手動で退避してください

## ロール一覧

| ロール | 日次入力（実績・食事単価の保存） | 月次集計・PDF出力 | マスタ管理 |
|--------|----------|----------|------------|
| 管理者 | ✅ | ✅ | ✅ |
| 一般スタッフ | ✅ | ✅ | ❌ |
| 閲覧のみ | ❌ | ✅ | ❌ |

- 権限は画面の表示だけでなくサーバー側（API）でも判定します。権限のない操作は `403` で拒否されます
- マスタ管理（患者・物品・日用品単価・ユーザー・病棟の登録／変更／削除）は管理者のみです
- 有効な管理者が1人もいなくなるユーザー変更・削除はできません

## データについて

- データベースは `data/hiyou.db` に保存されます（環境変数 `DB_PATH` で変更可）
- 保存は一時ファイル（`hiyou.db.tmp`）へ書いてから差し替える方式です（保存の途中で電源が落ちても、DBファイルは直前の完全な内容のまま残ります）。DBファイルが0バイトのときは、空のDBで上書きせずに起動を止めます
- バックアップは `tools/backup-hiyou.ps1` を使ってください（コピー後に中身を検査し、世代を残します）。手順は [配置手順/2_運用編.md](配置手順/2_運用編.md)
- 日次入力の「一括保存」は、変更した欄だけを送ります（同じ患者・同じ月を2人が開いていても、互いの入力を古い値で上書きしません）
- 日用品単価は月ごとに設定でき、未設定の月は直近の過去月の設定値を自動引き継ぎします（マスタ画面・日次入力・月次集計・請求書PDFすべて共通。参照ロジックは [server/services/prices.js](server/services/prices.js) に集約）
- 食事単価・食事費上限は患者ごと・月ごとに設定可能です（こちらも未設定の月は直近の過去月から引き継ぎます）
