# 療養介護サービス提供実績記録票

入院患者が1か月に利用した日用品・食事などの費用を自動集計し、請求書（PDF）を出力する社内向けWebアプリケーションです。

---

## 主な機能

| 機能 | 内容 |
|------|------|
| **日次入力** | 患者ごとに日用品の使用数・食事回数・サービス提供状況を1か月分まとめて入力 |
| **月次集計** | 病棟・月を指定して全患者の費用を一覧表示 |
| **PDF出力** | 患者ごとの請求書をPDFで出力 |
| **マスタ管理** | 患者・物品・日用品単価・ユーザーの登録・編集・削除 |
| **ロール制御** | 管理者／一般スタッフ／閲覧のみ の3段階アクセス制御 |
| **ログインの保護** | パスワードの強度チェック（13文字以上・英数字混在）、ログインに続けて失敗したときの一時ロック（接続元ごと） |
| **操作ログ** | ログイン、患者の情報の表示・PDF出力、登録・変更・削除を「いつ・だれが・どのPCから・どの患者に」で記録し、管理者が画面で確認・CSV保存 |
| **週次使用量レポート** | 毎週月曜6:00に前週の日用品使用量を品目別に集計し、Difyワークフローへ送信（Dify側でメール配信） |

---

## 画面構成

```
├── 日次入力
│   ├── 病棟選択（2階 / 3階 / 4階）
│   ├── 患者選択
│   └── 1か月分の日次入力テーブル
│       ├── サービス提供の状況・入院外泊時加算・入院時支援特別加算
│       ├── 朝食・昼食・夕食（回数）
│       └── 日用品項目（入浴〜洗濯 など）
│
├── 月次集計
│   ├── 病棟選択
│   └── 患者別 食事費・日用品費・合計金額一覧
│
└── マスタ管理
    ├── 患者管理
    ├── 物品管理
    ├── 日用品単価（月ごと設定・翌月以降引き継ぎ）
    ├── ユーザー管理（パスワードの基準、ロックの解除）
    └── 操作ログ（期間・ユーザーID・種類で絞り込み、CSV保存）
```

## セットアップ

### 必要環境

- Node.js 22.12 以上（推奨は現行の LTS。2026年11月時点では 26 系）。請求書PDFに使う Puppeteer 25 が 22.12 以上を必要とします

### インストールと起動

```bash
git clone https://github.com/aki2228824/hiyou-keisan.git
cd hiyou-keisan
npm install
node server/index.js
```

ブラウザで `http://localhost:3000` にアクセスしてください。

`npm install`（または `npm ci`）のときに、請求書PDF用の Chrome（約 440MB）がプロジェクト内の `.cache` にダウンロードされます。取得に失敗しても npm は成功したように見えるので、起動時のログに「請求書PDF用の Chrome が見つかりません」と出た場合は `npx puppeteer browsers install chrome` を実行してください。

### 初期ログイン情報

| ユーザーID | パスワード | ロール |
|-----------|-----------|--------|
| admin | admin123 | 管理者 |

> 初期管理者は、ユーザーが1人も登録されていない初回起動時にだけ自動作成されます（そのとき起動ログにも表示されます）。
> ログイン後、マスタ管理 → ユーザー管理からパスワードを変更してください（初期パスワードのままログインすると、画面の上部に注意が出ます）。
> 新しいパスワードは下の「ログイン・パスワード・操作ログ」の基準を満たす必要があります。

## 週次使用量レポート（Dify連携）

毎週月曜 6:00（JST）に前週（月〜日）の日用品使用量を品目別・病棟別に集計し、Dify のワークフローAPIへ送信します。メール本文の生成と配信は Dify 側で行います。

**送信するデータには個人情報を含めません。** 患者名・patient_id・受給者証番号・部屋番号は一切送らず、品目別／病棟別の集計値と在院患者数のみを送信します。

### 集計仕様

- 対象期間：前週の月曜〜日曜（比較対象は前々週の月曜〜日曜）
- 対象品目：`items.active=1` の全品目。ただし除外品目（**入浴・バスタオル・小タオル**）と、先週・前々週とも0の品目は除外
  - 入浴＝サービス、タオル類＝リネン業者のレンタル品のため補充目安の対象外
  - 除外リストは [server/services/weeklyUsage.js](server/services/weeklyUsage.js) の `EXCLUDED_ITEM_NAMES` 定数（items.name と完全一致で判定）
  - 除外が効くのは週次レポートの集計のみ。月次集計・請求書PDFなど請求側の処理には影響しません
- 並び順：先週使用量の多い順
- フラグ（判定はすべてサーバー側で行い、LLMには計算させません）
  - `急増`：増減率 +30% 以上 かつ 先週合計 10 以上
  - `使用停止`：前々週に使用があり、先週が0
  - 前々週が0の品目（新規使用）は増減率を計算できないため `pct: null`・フラグなし
  - しきい値は [server/services/weeklyUsage.js](server/services/weeklyUsage.js) 冒頭の定数（`SPIKE_PCT` / `SPIKE_MIN`）で変更できます
- 退院済み患者（`patients.active=0`）の期間中の実績も含みます
- 本機能はDBの**読み取りのみ**で、書き込み・保存は行いません

### 環境変数（.env）

`.env.example` をコピーして `.env` を作成してください（`.env` はGit管理外です。APIキーをコミットしないこと）。

| 変数 | 内容 |
|------|------|
| `DIFY_API_URL` | DifyワークフローのAPI URL（例：`https://api.dify.ai/v1/workflows/run`） |
| `DIFY_API_KEY` | Difyで発行したAPIキー（`app-` で始まる文字列） |
| `EXPORT_ENABLED` | `true` のときだけ週次ジョブを登録する |
| `EXPORT_CRON` | cron書式（既定 `0 6 * * 1` ＝ 毎週月曜6:00） |
| `EXPORT_DRY_RUN` | `true` にすると自動実行時もDifyへ送信せずログのみ記録 |
| `TZ` | `Asia/Tokyo` |
| `SESSION_SECRET` | ログイン状態（セッション）の署名に使う秘密の文字列。本番運用では長いランダム文字列を設定する（未設定時は既定値。変更すると全員が再ログインになる） |
| `PORT` | 待ち受けポート番号（未設定時は `3000`） |
| `DB_PATH` | データベースファイルの保存先（未設定時は `data/hiyou.db`。相対パスは、起動した場所ではなくプロジェクトのフォルダから見た場所として読む。親フォルダが無ければ自動作成） |
| `PDF_CONCURRENCY` | 請求書PDFを同時に生成する数の上限（未設定時は `2`。超えた分は順番待ち） |
| `PASSWORD_MIN_LENGTH` | パスワードの最小文字数（未設定時は `13`。8 未満にはできない） |
| `LOGIN_MAX_FAILURES` | 同じPC（接続元）から、同じユーザーIDでログインに続けて失敗できる回数（未設定時は `5`。3〜20。すべてのPCの合計では、この 4 倍でどのPCからもログインできなくなる） |
| `LOGIN_LOCK_MINUTES` | 上の回数に達したときにログインできなくなる時間（分。未設定時は `15`。1〜1440） |
| `AUDIT_LOG_DIR` | 操作ログの保存先フォルダ（未設定時は、DBファイルと同じフォルダの `audit`。通常は設定しない） |
| `AUDIT_USER_PER_MINUTE` | 同じユーザーが、操作ログの対象になる操作を 1 分間に行える上限（未設定時は `6000`。600〜60000。超えた分は処理せずに断る。通常は設定しない） |
| `TRUST_PROXY` | HTTPS のリバースプロキシの背後で動かすときに設定する（同じ機械の Caddy なら `loopback`、NAS 内蔵のプロキシなら `1`）。未設定なら何も信用しない |
| `HOST` | 待ち受けるアドレス（`127.0.0.1` にすると、同じ機械のリバースプロキシ経由でしか接続できない。未設定時はすべてのネットワーク。未設定か `127.0.0.1` のどちらかで使う） |

`.env` は起動時の作業フォルダに関係なく、プロジェクト直下のものが読み込まれます。

### 手動実行API（管理者のみ）

```
POST /api/export/weekly-usage/run
  ?dry=1             Difyへ送らず集計JSONをそのまま返す（同期・テスト用）
  ?date=YYYY-MM-DD   基準日を指定して過去週を集計する（テスト用）
```

`dry` なしの実行は、集計後すぐに `202 Accepted`（対象期間・品目数）を返し、Dify への送信とリトライはバックグラウンドで行います（リトライで最大21分かかるため）。結果は `data/export.log` を確認してください。

```bash
# 管理者でログインしてドライラン
curl -c cookie.txt -H "Content-Type: application/json"   -d '{"username":"admin","password":"admin123"}' http://localhost:3000/api/auth/login
curl -b cookie.txt -X POST "http://localhost:3000/api/export/weekly-usage/run?dry=1"
```

Windows の PowerShell から実行する場合（ユーザーIDとパスワードは管理者のものに置き換える）：

```powershell
$s = New-Object Microsoft.PowerShell.Commands.WebRequestSession
Invoke-RestMethod -Uri 'http://localhost:3000/api/auth/login' -Method Post -ContentType 'application/json' -Body '{"username":"admin","password":"パスワード"}' -WebSession $s
Invoke-RestMethod -Uri 'http://localhost:3000/api/export/weekly-usage/run?dry=1' -Method Post -WebSession $s   # ドライラン（送信しない）
Invoke-RestMethod -Uri 'http://localhost:3000/api/export/weekly-usage/run' -Method Post -WebSession $s         # 実際に送信する（月曜6:00の分を送り直すとき）
```

### 送信の失敗時

Dify へ送れなかった場合は 1分 → 5分 → 15分 の間隔で最大3回リトライします。最終的に失敗してもサーバー本体は停止せず、`data/export.log` にエラーを記録します。

### 運用上の注意

- PM2 等で複数プロセスを起動すると cron が重複実行されます。**単一インスタンス運用が前提**です
- ログ `data/export.log` は追記のみです。肥大化する場合は定期的に手動で退避してください

## ログイン・パスワード・操作ログ

厚生労働省「医療情報システムの安全管理に関するガイドライン 第7.0版」（システム運用編 14章・17章）が求める内容に合わせています。運用のしかた（月次の確認、ロックの解除、管理者がログインできなくなったとき）は [配置手順/2_運用編.md](配置手順/2_運用編.md) の 8章にまとめています。

### パスワードの基準

ユーザーの追加時と、パスワードの変更時にサーバー側で確かめます（満たさないものは登録できず、理由が表示されます）。

- 13文字以上（`.env` の `PASSWORD_MIN_LENGTH` で変更可）、72文字以内
- 半角の英字と数字を両方含む（記号も使えます。全角文字・日本語は使えません）
- ユーザーID、推測されやすい文字列（password・admin などのよくある語、hiyou・keisan・byouin・hospital・ryouyou・kaigo のような施設や業務に関係する語、qwerty・1q2w3e などのキーボードの並び。pa55word のように数字や記号で置き換えたものも含む。断られたときは、当たった語が表示されます）、同じ文字の4回以上の連続、順番に並んだ文字（12345・abcde）、同じ並びの繰り返し（abc123abc123）を含まない。6種類以上の文字を使う
- 変更のときは、現在のパスワードと同じものは不可

この基準ができる前に登録されたパスワードや、初期の `admin123` でもログインはできますが、ログインのたびに画面の上部へ注意が出ます。パスワードを設定できるのは管理者だけです（本人が変更する画面はありません）。定期的な変更は求めません。パスワードを変更すると、そのユーザーがログイン中だった画面は次の操作から使えなくなります（ログインし直しになります）。

### ログイン失敗時のロック

- 同じPC（接続元）から同じユーザーIDで 5 回続けてログインに失敗すると、そのPCからは、そのユーザーIDで 15 分間ログインできなくなります（正しいパスワードでも不可）。ほかのPCからはログインできます
- PCを変えながら失敗を続けた場合は、合計 20 回で、どのPCからもそのユーザーIDでログインできなくなります（15 分間）
- 15 分たてば自動で戻ります。管理者は、マスタ管理 → ユーザー管理 の「ロック解除」ですぐに戻せます。パスワードを設定し直したときも解除されます
- 失敗の回数はサーバーのメモリ上で数えます。サーバーを再起動すると回数とロックは消えます
- ログイン済みの画面は、ロックの影響を受けません
- ログインの試行そのものにも上限があります（同じ接続元から 1 分間に 20 回まで、全体で 1 分間に 120 回まで）
- 管理者がパスワードを忘れたときは、サーバー機の上で `tools/reset-password.js` を使って設定し直せます（アプリを止めてから実行します。アプリが動いている間・DB が見つからないときは、何も変更せずに終わります）
- 患者の情報を表示・出力する要求は、URL の書き方にかかわらず必ず操作ログに残ります。`/` を重ねたURL・`%00` を含むURLは処理せずに断り、同じユーザーが 1 分間に 6,000 件を超える操作を送った場合も、超えた分は処理せずに断ります（記録に残らない表示・出力を起こさないため。2026-11-22 の再点検で追加。[動作検証.md](動作検証.md) の S-04）

### 操作ログ

- 記録するもの：ログインの成功・失敗・ロック・ログアウト、患者一覧・実績・月次集計・食事単価の表示、請求書PDFの出力、登録・変更・削除（権限が無くて断られたもの、入力の誤りで断られたものを含む）、ユーザー管理の操作、操作ログそのものの表示、サーバーの起動
- 1件ごとに、日時（サーバーの時刻）・ユーザーID・ロール・接続元のIPアドレス・操作の種類・対象の患者ID・結果・変更の内容を残します。**パスワードは記録しません**（`***` に置き換えます）。ログインに失敗したときに入力された文字列は、登録されているユーザーIDのときだけ残します
- 保存先は DB とは別のファイルです：DBファイルと同じフォルダの `audit\audit-YYYY-MM.jsonl`（1か月1ファイル、1行が1件）。追記だけを行い、アプリから書き換え・削除はできません。自動では消しません
- 管理者は、マスタ管理 → 操作ログ で、期間・ユーザーID・種類（ログイン・ログアウト／表示・出力／登録・変更・削除／断られた操作・エラー）・キーワード（患者の氏名でも探せます）で絞り込んで確認し、CSV で保存できます
- 病棟・物品・単価の一覧のような参照用データの表示と、画面のファイルの取得は記録しません
- 未ログインの要求は、内容を記録せず、1件ずつ記録するのは1分間に 120 件までです（超えた分は件数だけを記録します。実在するユーザーへのログイン失敗は、この上限に関係なく記録します）
- 操作ログには患者IDや変更内容が含まれます。DB と同じ扱い（フォルダの権限、バックアップ）で管理してください。`tools/backup-hiyou.ps1` は操作ログも複製します

## データについて

- データベースは `data/hiyou.db` に保存されます（環境変数 `DB_PATH` で変更可）
- 保存は一時ファイル（`hiyou.db.tmp`）へ書いてから差し替える方式です（保存の途中で電源が落ちても、DBファイルは直前の完全な内容のまま残ります）。DBファイルが0バイトのときは、空のDBで上書きせずに起動を止めます
- バックアップは `tools/backup-hiyou.ps1` を使ってください（コピー後に中身を検査し、世代を残します。操作ログも複製します）。手順は [配置手順/2_運用編.md](配置手順/2_運用編.md)
- 操作ログは DB とは別に、DBファイルと同じフォルダの `audit` に保存されます（環境変数 `AUDIT_LOG_DIR` で変更可）
- 日次入力の「一括保存」は、変更した欄だけを送ります（同じ患者・同じ月を2人が開いていても、互いの入力を古い値で上書きしません。ただし朝食・昼食・夕食・サービス提供の状況・加算2つの計6欄は1日分をまとめて送るため、同じ日のこの6欄を2人が別々に直した場合は、後から保存した人の画面の値になります）
- 日用品単価は月ごとに設定でき、未設定の月は直近の過去月の設定値を自動引き継ぎします（マスタ画面・日次入力・月次集計・請求書PDFすべて共通。参照ロジックは [server/services/prices.js](server/services/prices.js) に集約）
- 食事単価・食事費上限は患者ごと・月ごとに設定可能です（こちらも未設定の月は直近の過去月から引き継ぎます）

| `tools/selftest-security.js` | パスワードの基準・ログイン失敗時のロック・操作ログの自己テスト（サーバーを起動せず、一時フォルダだけを使う） |
| `tools/reset-password.js` | 非常用。管理者がパスワードを忘れたときなどに、サーバー機の上でパスワードを設定し直す（アプリを止めてから実行する。操作ログに残る） |
| `tools/smoke-test.js` | 回帰テスト。現在のDBのコピーでサーバーを一時的に起動し、ログイン・権限・月次集計・請求書PDF・週次レポートのドライラン・パスワードの基準・ロック・操作ログを確認する（元のDBと本番の操作ログには書き込まない）。コードを変更したら push の前に実行する |
