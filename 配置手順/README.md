# 配置手順（社内サーバーに置いて、複数のPCから使う）

このアプリを開発PCではなく常時稼働のサーバー機に置き、社内ネットワーク（LAN）内の複数のPCのブラウザーから使えるようにするための手順書です。2026-11-21 作成。

## 結論

- **常時稼働できる Windows PC を1台用意し、Windows サービスとして動かす**のが最も確実です。手順は [1_Windowsサーバー編.md](1_Windowsサーバー編.md)。
- NAS は、Synology / QNAP の Intel・AMD 機（メモリ 4GB 以上）ならコンテナで動かせます（[3_NAS-Docker編.md](3_NAS-Docker編.md)。**Docker 上では未テスト**）。Buffalo や I-O DATA の NAS では動かせないので、バックアップ先として使います。
- どの方式でも、**サーバープロセスは1つだけ**です。NAS の共有フォルダに DB やプログラムを置いて各PCで起動する使い方はできません（互いの入力を上書きして消します）。
- 切り替えの段取り、バックアップ、セキュリティは [2_運用編.md](2_運用編.md) にまとめています。

| 手元にある機器 | 進め方 |
|---|---|
| 常時稼働できる Windows PC／Windows Server | 1編 → 2編 |
| Synology / QNAP（Intel・AMD、メモリ 4GB 以上） | 3編 → 2編。または Windows PC で動かし、NAS はバックアップ先にする |
| Buffalo・I-O DATA などの NAS だけ | アプリは Windows PC（1編）、NAS はバックアップ先（2編 2-4 の A） |
| まだ何も無い | 数年前の事務用PCやミニPCで足ります（1編 §1 の目安） |

## 作業の流れ（Windows の場合）

1. 開発PCの Node.js を 26 LTS に上げて動作確認する（1編 Step 0）
2. サーバー機を用意する：IP 固定、スリープ無効、Node.js と Git のインストール（1編 Step 1〜2）
3. フォルダを作って権限を絞り、コードを置く（1編 Step 3〜4）
4. `.env` を作る。DB は空から始める（1編 Step 5）
5. 手動で起動して確認 → 初期パスワード admin123 を変更（2編 1-2 の 6。LAN に開ける前に必ず）→ Windows サービスにする → ファイアウォール（1編 Step 6〜8）
6. 別のPCから確認し、再起動しても自動で立ち上がることを確かめる（1編 Step 9）
7. 個人別アカウントの作成（2編 1-2 の 7。初期パスワードの変更は手順 5 で済ませておく）
8. バックアップのタスク登録と復元テスト（2編 2-3、2-5）
9. 開発PC側の週次レポートを止める（2編 1-2 の 8）

## 2026-11-21 にコードへ入れた対応

複数のPCで使う前の点検で見つかった問題を修正し、テストしてあります（詳細は [動作検証.md](../動作検証.md) の S-02）。

- DB の保存を「一時ファイルに書いてから差し替え」にした（保存中の停電・異常終了で DB が壊れない。0バイトの DB を空の DB として上書きしない）
- 実績の保存で DB 全体を書き出す回数を、1日分につき最大16回から1回にした
- 日次入力の「一括保存」が、変更した欄だけを送るようにした（2人が同じ患者・同じ月を開いていても、互いの入力を古い値で上書きしない。ただし朝食・昼食・夕食・サービス提供の状況・加算2つの計6欄は1日分をまとめて送るので、同じ日のこの6欄を2人が別々に直すと、後から保存した人の画面の値になる）。未保存の入力があるときは切り替え前に確認を出す
- `.env` と PDF 用 Chrome の場所を、起動時の作業フォルダやアカウントに関係なく見つかるようにした（Windows サービスで動かすための対応）
- 請求書 PDF の同時生成数を制限した（既定2。メモリ不足の防止）
- バックアップ・稼働確認・初期パスワード確認・保存処理の自己テストのスクリプトを `tools/` に追加した

開発PC（管理者権限なし、Docker なし）では試せなかったものです。サーバー機での確認手順は各編に入れてあります。

| WinSW によるサービス登録、起動時の自動開始、異常終了後の自動再起動 | 1編 Step 7 の確認 1〜3 |
| サービス（LocalSystem）からの Chrome 起動＝PDF 出力 | 1編 Step 7 の確認 4 |

## 決めていただくこと

1. **サーバーにする機器**（機種、Windows のエディション、有線LANか、専用機にできるか）。NAS を使うならメーカーと型番
2. **夜間・週末も電源を入れたままにできるか**（月曜 6:00 の週次レポート送信と夜間バックアップの前提）
3. **Wi-Fi で使うPCがあるか、来客や業者の機器が同じネットワークにつながるか**（あるなら最初から HTTPS にする。2編 3章）
4. **バックアップの2本目の置き場**（NAS か USB HDD）と保持期間、月次のオフライン保管の担当
5. **未署名のフリーソフト WinSW をサーバーに入れてよいか**（不可なら Servy かタスク スケジューラ方式。1編 §5）
6. **施設のルールとの関係**：厚生労働省ガイドラインの対象として台帳・規程に載せるか。操作ログ・二要素認証・パスワード強度チェックが無い点を、当面は運用で補うことの了承（2編 7章）
7. **GitHub リポジトリの公開設定**：2026-11-21 時点で公開（誰でも閲覧可）になっています。患者データや API キーは含まれていませんが、意図していなければ非公開に変えてください
8. 担当者が不在のときに、再起動と復元を行う代行者
